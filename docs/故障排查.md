# 故障排查

按“**症状 → 原因 → 怎么办**”组织。这里的每一条都是实际踩过的，不是推测。

先跑一次自检，多数问题能直接定位：

```powershell
cd Ember
pwsh -NoProfile -File scripts\health-check.ps1
```

## 自检结果的三种状态

| 状态 | 含义 | 要不要处理 |
|---|---|---|
| `OK` | 可用 | 不用 |
| `FAIL` | **真问题**：登录态过期、进程没起、源没接 | 要 |
| `SKIP` | **按设计未激活**（如 bsk 空闲自退） | 不用，用到时再开 |

`-Fix` 会尝试拉起 bsk 守护进程和纪念碑谷：

```powershell
pwsh -NoProfile -File scripts\health-check.ps1 -Fix
```

> ⚠️ `-Fix` 只“触发启动、不在同一次里验证”，所以跑完要再跑一次自检确认。
> 在 **agent 环境**里 `-Fix` 可能不可靠（见文末“沙箱与代理执行”）。

## 微信

### `weflow-cli` 卡住或返回空

**原因**：微信没登录/没运行，或数据库被占用。
**处理**：

```powershell
weflow-cli scan          # 看能不能找到账号与数据目录
weflow-cli dbkey         # 从运行中的微信进程取密钥（需要微信开着）
weflow-cli sessions      # 能列出会话就说明通道正常
```

### 导出的消息全是“未知”或条数对不上

**原因**：weflow 导出的 JSON 是**数组**（每条消息一个元素，字段是 `senderDisplay/createTime/parsedContent`），
而不是 `{ messages: [...] }`。老解析器会把它当成空。
**处理**：确认走的是 `_parseWechatExportArray`（Ember 已支持）。自查：

```bash
node -e "const a=require('./data/raw/wechat/xxx_messages.json'); console.log(Array.isArray(a), a.length)"
```

### 群名显示成 `12345678@chatroom`

**原因**：导出文件名只有 talker ID，群名不在文件里。
**处理**：把会话列表里的 `displayName` 写进 `data/raw/wechat/_names.json`，`build-from-data.mjs` 会查表补上。

## QQ

### 自检显示 `0/3 在线` / 端口 3000/3002/3003 无监听

**原因**：QQ 客户端在跑，但 **NapCat 没注入**（OneBot 桥没起）。
**处理**：

```powershell
cd qchat-cli
.\start-all-napcat.cmd        # 三个号分别扫码
```

注入前建议先关掉已运行的 `QQ.exe`，否则容易失败。
确认：

```powershell
cd qchat-cli
node dist\cli.js account list
node dist\cli.js napcat status
```

### `EPERM: open '...\loadNapCat.js'`

**原因**：代理进程（agent/沙箱）无权写 `%USERPROFILE%\.qchat-cli`。
**处理**：这一步必须**由用户在自己的终端里执行**，或者给代理放宽目录权限。

### `消息undefined不存在` / 导出 0 条

**原因**：NapCat 只保存**它启动之后**的消息。历史消息如果当时没在线，就是没有。
**处理**：换别的目标试试，或接受“从现在开始积累”。QQ 空间那部分不受影响（它在服务器上）。

## QQ 空间

### `code=-3000` / `请登录空间` / `Session expired`

**原因**：cookie 过期。实测寿命约 **13 小时**（前一天晚上扫、次日上午就失效）。
**处理**：

```powershell
cd qchat-cli
qce qzone login --force
```

多号并存时，每个号各扫一次，Ember 会按 `.qzone-cookie.<uin>` 分别读。

### `-4003 错误的统计年份` / `空间号码错误`

**原因**：**不是接口下线**，是参数不对。`get_abs` 要求驼峰参数（`hostUin/blogType/sortType/absType/reqInfo=1`），
`uin` 必须是**已登录的自己**，把目标号填进 `uin` 就会报这个。

> 这个坑我判断错过一次：一开始把 `-4003` 当成“接口停用了”。实际是参数问题，接口一直活着。

### 说说/评论数比预期少

**原因**：`qce qzone feeds` 默认每页 20 条，评论内嵌在 `commentlist`；翻页要显式给 `--pos`。
**处理**：Ember 会按 `--num/--pos` 分页直到取够。

## 飞书

### `The refresh token has been revoked`

**原因**：令牌有两个存放位置，wrapper 只读了一个。飞书的 refresh token 是**一次性的**，读错那份就等于把它用掉。

| 位置 | 说明 |
|---|---|
| `~/.lark-cli/user-token.json` | 规范位置 |
| 启动注入的 `_zc_tmp/lark-token/token.json` | 引导用 |

**处理**：wrapper（`Ember/scripts/lark-cli-user-token.js`）现在会**两个都读、按 `expires_at` 取较新的**。
如果已经 revoked，重跑一次 device flow：

```powershell
powershell -File _zc_tmp\lark-token-flow2.ps1
```

（会给出一个链接+码，需要你在浏览器里确认一次。）

## 贴吧 / 知乎

### `浏览器通道不可用` / `no browsers connected`

**原因**：bsk 守护进程**空闲 10 分钟就自退**（日志：`daemon exceeded idle threshold; exiting`, `idle_secs: 600`）。这是设计行为，不是崩溃。
**处理**：打开 Edge，让 browser-skill 扩展连上，用到时再操作。

确认：

```powershell
bsk browsers        # 有输出的第一列是 8 位实例 ID
```

### `bsk daemon start` 卡住不返回

**原因**：`bsk daemon start` 是**前台常驻**进程，在脚本/代理里直接调用会让调用方一直等。
**处理**：用 `Start-Process` 脱离，或干脆让守护进程按需自启（任何 `bsk` 子命令都会尝试拉起它）。

> 不要在没有 daemon 的情况下调 `bsk browsers`：它会尝试自启并卡住，连 `Stop-Job` 都停不下来。
> 自检脚本因此改成**先看 `daemon.json` 里的 pid 是否活着**，不健康就完全不调 bsk。

### 贴吧帖子楼层是相对时间（“3 分钟前”）

**原因**：贴吧页面只给相对时间。
**处理**：`_parseRelTime` 以抓取时刻为基准换算成绝对秒；抓取时间和真实发帖时间会有分钟级误差。

## 纪念碑谷（valley）

### `3001` 连不上 / `ERR_CONNECTION_REFUSED`

**原因**：服务没起，或随会话/机器重启被回收。
**处理**：

```powershell
Ember\scripts\start-valley.cmd     # 后台启动，日志写到 logs\
```

验证：

```powershell
curl http://127.0.0.1:3001/api/monuments
```

### `JWT_SECRET 未设置` / 启动即退出

**原因**：`valley/server/.env` 缺失或没写 `JWT_SECRET`。
**处理**：

```powershell
cd valley\server
copy .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # 填进 JWT_SECRET
```

### `better-sqlite3` 编译失败

**原因**：Node 版本太新（如 24），原生模块没有预编译包，gyp 编译失败。
**处理**：不用管。`valley/server/db/init.js` 会自动回落到内置 `node:sqlite`，功能一致（会有 ExperimentalWarning）。

## 数据汇总与合并

### 多个平台的会话被合成一个

**原因**：联系人去重只按 `chatId`。
**处理**：键要取 `chatId || id || name`（`merge.js` 已修）。

### 隐私数据差点被提交

**原因**：`data/` 是个人数据目录。
**处理**：`.gitignore` 已忽略 `data/raw|unified|analysis|output` 与 `logs/`，只有 `data/README.md` 入库。
自查：

```powershell
git check-ignore -v data/raw/xxx data/analysis/analysis.json
```

## 沙箱与代理执行

以下限制**只影响由 agent/自动化调用时**，用户在自己终端里没有这些问题：

| 现象 | 原因 | 绕过办法 |
|---|---|---|
| `EPERM: open 'C:\Users\...\.qchat-cli\loadNapCat.js'` | 代理无权写用户目录 | 用户手动跑 `start-all-napcat.cmd` |
| `Invoke-CimMethod Win32_Process Create` → `拒绝访问` | 沙箱禁止 WMI 创建进程 | 用 `Start-Process`（但会拖住调用方） |
| `Start-Process` 后调用方一直不返回 | 子进程继承了句柄/前台常驻 | 放到后台作业里触发，或让用户执行 |
| `schtasks` / `Register-ScheduledTask` → `拒绝访问` | 需要管理员权限 | 用户以管理员身份执行一次 |
| npm 全局安装失败 | 代理无权写 `%APPDATA%` | 用户手动 `npm i -g` |

## 一句话总结

大部分“故障”其实是三类：

1. **登录态过期**（QQ 空间 13 小时、飞书 refresh 一次性、NapCat 要扫码）
2. **进程没起**（NapCat 桥、bsk 守护进程、valley 服务）
3. **权限边界**（代理写不了用户目录、创建不了计划任务）

真正的代码 bug 反而少。遇到问题先问一句：**是登录态、进程，还是权限？**
